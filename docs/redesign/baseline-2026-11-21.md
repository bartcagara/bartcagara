# Homepage funnel baseline, 23 Aug to 21 Nov 2026 (90 days)

Read-only. Sources: PostHog EU project 97157 (events table, HogQL) and Cal.com event type 492404.
Filter used everywhere (call it F): host `bartcagara.com`, event country not `PL`,
`utm_term` not `tracking-fix-verification`. Homepage = `$pageview` with `$pathname='/'`.
Persons = PostHog `person_id`. Not stitched across domains (see caveats).
I ran raw HogQL, not the typed runners; I did not apply the project's test-account filter.

## 1. Homepage traffic
- 136 unique persons, 244 pageviews (90 days). 112 persons remain if events flagged `$virt_is_bot` are removed.
- Per month (persons / pageviews): Aug 23-31: 7 / 9. Sep: 39 / 71. Oct: 50 / 115. Nov 1-21: 45 / 49.
  (Monthly persons add up to 141, more than 136, because people return in later months.)
- Whole bartcagara.com for context: 331 persons (all pages, F applied).
- Query: `SELECT toStartOfMonth(timestamp), countIf($pathname='/'), uniqIf(person_id,$pathname='/') FROM events WHERE event='$pageview' AND F GROUP BY 1`.
- `app.bartcagara.com` (the Stack app, 2,520 views), localhost, 127.0.0.1 and *.pages.dev are excluded.

## 2. Homepage to booking page
- Same person, booking page AFTER first homepage view: 1 of 136 (via `/book`). 0 via cal.com direct, 0 via the embed.
  Booking pages = `/book` + cal.com `/bartcagara/discovery-call` + app.cal.com `.../embed`.
- This understates reality: Cal.com events are a different person id from the website visit. Better proxy,
  booker loads (embed) whose referrer is bartcagara.com: 103 loads, 81 persons, 86 sessions. The embed
  does not say which page hosted it (`/` or `/book`), so I can't split those.
- Booking page totals, non-Poland, 90 days: `/book` 25 views / 25 persons (since 31 Oct);
  cal.com direct `/bartcagara/discovery-call` 20 views / 19 persons; `/restart-audit` 2; embed 103 loads / 81 persons.
- Book button on homepage: no custom event. Only `$autocapture` clicks exist. Clicks on text
  "BOOK MY RESTART AUDIT" or "Book My Call": 12 clicks by 5 persons (first one 27 Aug).
  Any homepage click at all: 24 persons. Query: `$autocapture`, `$event_type='click'`, `$pathname='/'`, text from `elements_chain`.
- Other onward steps from the homepage (same person, after): to `/brief` or `/briefing-optin` 9; to a newsletter signup 3; to `/contact` 17.
  Homepage "Coaching" link clicks 9 (7 persons); "The Brief" nav link clicks 27 (persons not counted).

## 5. Where homepage visitors came from (persons) and device
- Direct 106, newsletter (utm_source) 17, Google 9, LinkedIn 3, Instagram 1, other 2 (YouTube, a spam domain, self-referral).
- Desktop 122 persons, mobile 14 (a person can show on both). Pageviews: 191 desktop, 53 mobile. Mobile is only about 10% of homepage persons. LinkedIn traffic is under-counted: the LinkedIn app often arrives as "direct".

## 6. Scroll depth on `/`
- `$pageleave` with `$prev_pageview_max_scroll_percentage` exists, but only 72 leaves for 244 views (leave events are missed on many exits). Median 38%; reached 50%: 32 of 72 (44%); reached 90%: 23 of 72 (32%).
- There is also a `landing_scrolled` event (175 events, 59 persons, since 31 Oct), not analysed.

## Caveats and what I could not confirm
- Poland exclusion is event-level by geoip country, not person-level.
- Cal.com visits are not linked to website persons, so the "homepage to booking page" count of 1 is a floor.
- Could not tell which website page loaded the embed.
- Did not run the typed runners (`query-funnel`) or the saved action 169979 directly.
- Possible bot traffic: 24 homepage persons flagged as bots (included above; the no-bot figure is 112).
